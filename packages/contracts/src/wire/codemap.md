# src/wire/

## Responsibility

Every wire protocol in the platform: HTTP request/response shapes for all endpoints (api.ts), the NDJSON generation event stream (generation.ts), the endpoint-wide error taxonomy (errors.ts), and the host↔guest sandbox message protocol (sandbox.ts).

## Design

- src/errors.ts is the taxonomy every client branches on: `ErrorCode` (14 codes, each documented), one body shape `ApiError` {error: {code, message, detail?, requestId, retryAfterSeconds?}}, and three frozen decision tables — `ERROR_STATUS` (a missing capability is `capability_absent → 503`, never 500; `cancelled → 499`), `RETRYABLE` ("retries for the transient, never for the semantic" — `bad_request`/`upstream_refused` false, `rate_limited`/`upstream_truncated` true), `DEFAULT_ERROR_MESSAGE` (learner-facing wording written once, next to the reason it exists).
- src/api.ts: validated at the route boundary — `GenerateRequest` (topic 5–500 chars; `MIN_TOPIC_LENGTH` exists because a 1-char topic wastes an AI call; `stream` boolean chooses NDJSON vs one JSON object with identical content), `GenerateResponse`, `ChatRequest`/`ChatEvent`, `QuizRequest`/`QuizResponse` (+`dropped` counter — invalid questions vanish, never render), gallery (`GalleryEntry` carries `snapshotUrl`, bytes never ride a list; `GalleryListQuery` coerces and bounds limit ≤ 60; `PublishRequest` snapshot sniffed by magic bytes server-side; optional `galleryId` targets an existing entry — the one auto-save minted or the one a model was loaded from — so a publish updates that row in place rather than adding a duplicate), `HealthResponse` (liveness separate from database-driven readiness; `capabilities.ai/database/snapshots`; `storage` enum). `COMPLEXITY_LEVELS` is the shared numbers table the landing page labels _and_ the server prompt derives from — the drift fix; `ModelContext` is the bounded tutor context (≤40 parts + `partsOmitted`, `selectedPartId`).
- src/generation.ts: `GENERATION_PHASES` exported as an _ordered array_ because phase order is part of the contract, plus `GenerationPhase` and nominal `PHASE_WEIGHT`. `GenerationEvent` is a discriminated union on `type`: `phase` / `heartbeat` (`phaseSeconds`, optional `charsWritten` proof-of-life) / `notice` (retry/repair/refine/downgrade/warning — repaired work is disclosed to diagnostics, not hidden) / `ready` (whole `ModelBundle` + `AuditSummary` + `modelId?: Uuid` + `galleryId?: Uuid`) / `error` (same `ErrorCode` taxonomy as non-streaming). `galleryId` is the entry the server's auto-save minted for this run; the viewer hands it to the publish path so a later Publish UPDATES that entry instead of adding a duplicate. Optional so servers with auto-save off (or predating it) and their clients — including the topic battery — keep parsing. Invariant: exactly one terminal event, guarded by `isTerminalEvent`; a stream that ends without one is itself an error. `HEARTBEAT_INTERVAL_MS` 10s and `STALL_HEARTBEATS` 4 make the client's stall detector a heartbeat _multiple_, distinguishing slow provider from dead socket.
- src/sandbox.ts: the narrowest, most explicit interface in the platform — defined as data so the same guest runs in a browser Worker and `node:vm` with no capability difference. `GateViolationKind` (8: syntax, module_syntax, dynamic_code, forbidden_global, unknown_api, prototype_access, shape_limit, unguardable_loop) → `GateResult` (ok/violations/byteLength/guardedLoops/apiCalls). `SandboxRequest` union: `build` (instrumented code only, never raw provider output; `tier`, `deadlineMs`, deterministic `seed`), `setParameter`, `frame` (host-clamped `dt ≤ 0.25`), `invoke`, `dispose`. `SandboxResponse` union: `built` (a validated `ModelManifest`) / `failed` (a fault is a _message_, never an escaping exception; `timedOut` flag) / `frameUpdate` — the zero-allocation hot path: flat number lists, `TRANSFORM_STRIDE = 10` floats per part (pos3+quat4+scale3), `MATERIAL_WRITE_STRIDE = 6`, id-indexed `visibilityWrites`, `metrics` record / `warning` / `alive` (watchdog tells slow from hung) / `disposed`. Self-enforced ceilings in `SANDBOX_LIMITS` (1.5 MB code, 20 s build deadline, 50 ms frame deadline, `frameOverrunLimit` 12 → pause-not-kill, 6 M total vertices, 20 M `maxLoopIterations`). The same file now carries the viewer-interaction types: `AnnotationPin`/`SetAnnotationsRequest` (id + world point only, capped at `MAX_ANNOTATIONS_PER_MODEL`) and the projection reply `ProjectedAnnotation` (a `visible:false` entry means "no honest screen position", never a mirrored coordinate), plus the model-authored label channel `ProjectedLabel`/`LabelProjectionResponse` (`labelPositions`, capped at `MAX_LABELS`; the word itself stays manifest data the page already holds, keyed by id, so only the position travels and only when a labelled part moved), and `VIDEO_CLIP_LIMITS` and the `VideoRecordingCapability` probe result the export menu reads before offering a record button.

## Flow

Server routes parse inbound bodies against api.ts request schemas, respond with typed responses or `ApiError` (apps/server/codemap.md). The pipeline emits `GenerationEvent` lines as NDJSON until one terminal `ready`/`error`; the web client (apps/web/codemap.md) parses them, advances milestones on `phase`, and counts missed heartbeats against `STALL_HEARTBEATS`. Sandbox side: host sends `build` → guest answers `built`/`failed`; then per-frame `frame` → `frameUpdate` plus `alive` during the authoring pass (packages/sandbox/codemap.md).

## Integration

- Depends on ../primitives.ts, ../manifest/model.ts (`ModelBundle`, `ModelManifest`), ../budgets.ts (`DeviceTier`); uses `AuditSummary` from generation.ts inside api.ts, and `ChatPersona` is imported back by ../settings.ts (see src/manifest/codemap.md, src/codemap.md).
- Consumers: apps/server Hono routes, services and pipeline (apps/server/codemap.md — src/services/codemap.md has the streaming implementation); web routes/lib/api clients (apps/web/codemap.md); sandbox worker host + node:vm host (packages/sandbox/codemap.md — its gate validates against `GateResult`, its watchdog against `SANDBOX_LIMITS`).
