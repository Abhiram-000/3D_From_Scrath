# apps/web/src/lib/components/

## Responsibility

Every interactive UI part the viewer hosts as a leaf component: the left-panel tutor chat, the six in-viewer modals/dialogs (code view, gallery, generate, quiz, share, settings), story mode, the annotation overlay, the export menu, plus `panel-branch.ts` — the pure predicate that decides which branch the right panel takes. Visibility is _not_ owned here: `routes/viewer/+page.svelte` mounts each one behind an `{#if}` flag and passes callbacks in.

## Design

- Props in via `$props()`, effects out as callbacks: every modal takes `onclose` plus a completion callback (`ontab`, `onload`, `ongenerated`, `onquality`) instead of touching page state; the page closes it by flipping its own flag. State ownership is per-component workspace only — `chat-panel-v1.svelte` owns `messages`/`input`/`thinking`/`streamingId`; `gallery-modal.svelte` owns `entries`/`search`/`offset`/`loadingModel` pagination; `generate-dialog.svelte` owns `topic`/`progress`/`AbortController`; `quiz-modal-v1.svelte` owns `answered`/`score`/`finished`; `story-mode.svelte` owns beat `index` + its two timers; `settings-modal.svelte` owns a local `draft`; `export-menu.svelte` owns only `open`. Model data (`manifest`, `story`, `questions`, `pins`, `projected`, `capability`) always arrives as props, never fetched inside.
- Settings are a contract object, not panel-local state. `chat-panel-v1.svelte` reads the persona from `lib/core/settings.ts:SettingsStore` (`UserSettings.chatPersona`, one storage key) and does a one-shot migration off the old competing `edu3d.persona` localStorage key — the second home that could silently disagree with a settings edit and win invisibly. `settings-modal.svelte` edits a local draft, `UserSettings.safeParse`s each patch, and emits the whole object plus the quality pin via `onchange`/`onquality`; it never reaches into the host. Its disabled-with-a-reason controls (`Shadows`, `Post-processing`, physics preference, reduced motion, sensitivity) exist because a switch that moves but changes nothing is a lie (`08`) and the `WorkerRequest` union carries no message for those manual overrides.
- `panel-branch.ts:panelShowsSelectedPart(selectedPart, selectedPartInfo)` returns true only for a non-empty `selectedPart` AND truthy info. The comment is the spec: `activePart` resolves `selectedPart ?? hoveredPart`, so embedding that resolution inline flipped the panel's top-level branch on every hover — destroying/rebuilding the overview's up-to-200 part buttons synchronously while the pointer crossed the canvas, and removing the keyboard-reachable part list. "Hover belongs to the tooltip. Selection belongs to the panel."
- `annotation-layer.svelte` owns drawing and the per-pin editing affordances only; placement (`host.pickPoint`), persistence and publication (`host.setAnnotations`) belong to the page, so the overlay is a pure function of props plus local draft state and never touches the host. A `visible: false` projection is not drawn — it has no honest screen position, and drawing it anyway would mirror a behind-camera pin to the wrong side. Only a pin takes pointer events (the scoped rules supply the `pointer-events: none` the shipped `.annotation-overlay` rule omitted), so orbit keeps every drag and placement click.
- `export-menu.svelte` renders what the device can actually do: `capability === null` reads "checking", `supported: false` disables the Record item _and shows the reason_ — a live-looking button that does nothing is exactly the lie `03` R8 refuses. The screenshot sizes are named from `SNAPSHOT_PRESETS`, the same table the worker renders from, so a label cannot promise a size the export does not produce. The elapsed-seconds/cap check lives here as well as in the worker: the worker's bound is the guarantee, stopping here keeps the countdown from counting past a clip that already ended.
- Story mode chains a beat's declared shots by their own durations (default flight when a beat names none), gated narration advances on `onend`/`onerror` so a synthesis failure never strands the beat, and the play/stop effect reads only the beat `index` — everything it reaches for is `untrack`ed because a page passing inline callbacks would otherwise re-run the effect on its own parameter write (`effect_update_depth_exceeded`; the page also passes stable named callbacks as the other half of the fix).
- Modal chrome is not re-implemented: components reuse `viewer.css`'s `.modal-overlay.active` / `.modal-container.glass-panel` shell; `code-view-modal.svelte` is deliberately _solid_ (`backdrop-filter:none`) because it stacks potentially thousands of lines of text over the live WebGL canvas (the compositor-freeze fix documented in `viewer.css`).

## Flow

- Chat: `send()` guards `thinking`, appends the user message, and calls `core/api.ts:chatStream` (`{message, persona, history (last 12, sans welcome id 0), context: toContext(manifest, selectedPart)}`); each `delta` creates-then-grows one assistant bubble (`streamingId`, `nearBottom` gates the per-fragment scroll), the terminal `done` carries the authoritative text, and a failure returns the input with an honest note. `render()` serves only text nodes with a constrained `**bold**` renderer; `onScroll`/`scrollToBottom` implement near-bottom auto-scroll (60px) and the jump button (>160px).
- Code view: `rawCode = $derived(peekBundleCode() ?? '(the model came from the reference set…)')`; tabs are lifted state (`ontab`); `copy()`/`download()` (Blob) work on the raw text or `JSON.stringify(manifest)`; meta chips report `manifest.cost.*` and `warnings`.
- Gallery: `onMount → refresh(true)` hits `GET /gallery?limit=24&offset=…&search=…`; a card calls `load(entry)` → `GET /gallery/{entry.id}` → `onload(code, name, runtime)`; broken loads surface `error` rather than navigating.
- Generate: `start()` runs `generateStream` with `detectTier()` and a 150ms `ProgressModel` tick; events feed `progress.apply` + dev-console logging; success stores via `storeBundle(...)` and hands over with `ongenerated(code, name, runtime)`; `cancel()` aborts; failure offers "Try Again" / "Keep current model".
- Quiz: caller supplies `questions` and `source` (`authored` = written for this exact model, `generated` = fetched); `answer()` locks options once per question id (score counts once), `next()`/`restart()` walk and reset; correct/wrong marks stay visible beside the explanation.
- Story: `play()` calls `onshot` per declared shot (or `onfocus(beat.targetPartId ?? null)` when the beat names none; a dangling target skips the move, not the narration), pushes `beat.setParameters` through `onsetParameter` — the page's single owner of parameter writes so beats join the same undo history — and `go(±1)`/Escape/close never trap the learner.
- Annotations: a fresh pin arrives blank, so its input opens once (a bare dot would read as a failed click) and `cancel()` drops a note with no words rather than leaving a stray dot; `commit()` skips an unchanged edit.
- Export: `takeScreenshot(preset)` calls `onscreenshot` and closes; `toggleRecording()` maps to `onstartrecording`/`onstoprecording`; results arrive on the page's `onSnapshot`/`onVideoClip`/`onRecordingFailed`.
- Share: `onMount → publish()` POSTs `/gallery` with `{bundle: {manifest, code: program.code ?? REFERENCE_MODEL_SOURCE, …(runtime)}, snapshot?}` and, only once the server answers 201, sets `shareUrl` (the link is a promise — never a URL that 404s) and draws the link as a real QR via `core/qr.ts` (or says "QR unavailable"); `social()` opens prebuilt intent URLs; a 401 shows the one-token prompt instead of a dead end.

## Integration

- Sole consumer: `routes/viewer/+page.svelte`; the right panel's branch test there is `{#if selectedPartInfo && panelShowsSelectedPart(selectedPart, selectedPartInfo)}` — behaviour pinned by `panel-branch.test.ts` (hover-only info must stay on the overview; a selection with no info must not open an empty panel).
- Calls `$lib/core/api.ts` (`chatStream`, `generateStream`, `storeBundle`, `peekBundleCode`, `peekBundleRuntime`, `apiFetch`), `$lib/core/qr.ts` (`encodeQr`, `drawQr`, `qrPixelSize`), `$lib/core/settings.ts` (`SettingsStore`, `narratePart`), `$lib/core/model-context.ts:toContext`, `$lib/core/loading-progress.ts` (`ProgressModel`, `STAGES`), `$lib/dev-console.ts`, `$lib/engine/sandbox-host.ts` (`detectTier`, `SNAPSHOT_PRESETS`, `SnapshotPreset`); `annotations.ts` types come from `$lib/annotations/annotations.ts` via props only. Theme is page-level (`setTheme`), not these components.
- Contracts: `ModelManifest`, `ChatPersona`, `QuizQuestion`, `StoryBeat`, `ShotDecl`, `UserSettings`, `DeviceTier`, `QualityPreset`, `Annotation`, `ProjectedAnnotation`, `VideoRecordingCapability` from `@edu3d/contracts`; server endpoints `POST /chat`, `GET /gallery`, `GET /gallery/:id`, `POST /gallery`, `POST /generate` (through `generateStream`).
