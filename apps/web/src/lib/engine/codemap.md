# apps/web/src/lib/engine/

## Responsibility

The client-side engine host: the main-thread side of the sandbox boundary (`sandbox-host.ts`), the worker where all rendering happens on the learner's device (`sandbox-worker.ts`), and the DOM-free arithmetic extracted from the worker's hot path (camera glide, frame compose/rate, physics, quality, watchdog) so each rule can be tested without a GPU.

## Design

- **Protocol.** `sandbox-worker.ts:WorkerRequest`/`WorkerResponse` are the typed message dialects; `worker.postMessage` transfer-lists the `OffscreenCanvas`. `SerializableVerdict` strips the `Map`/`Set` fields of the engine's `AdmissionVerdict` so it survives structured clone.
- **Host.** `sandbox-host.ts:SandboxHost` owns the `<canvas>` because `transferControlToOffscreen()` is once-per-element — after any kill, `recreateCanvas()` replaces the spent element and `spawnWorker()` re-transfers. One worker per model: `load()` terminates the previous worker, so GPU objects, WASM heap and closures die with the realm (leak fix and correctness fix). Worker events are scoped to the worker they came from — a terminated worker's already-posted `MessageEvent` is ignored, so a stale `loaded`/`stats`/`error` can never touch the live host. `kill()` resets `buildingUntil`, pauses the empty replacement worker until a retry, and respawns on a fresh canvas. Every callback set is optional (`HostCallbacks`). The host forwards the newer capabilities without interpreting them: `resetCamera()` (the camera half of Reset, an absolute command rather than a reload), `pickPoint(x,y)` (a promise settled by the worker's `pickedPoint`, and settled as a miss whenever the worker is discarded so it cannot leak a promise the page awaits all session), `setAnnotations(pins)` (id + world point only; an empty array switches the worker's projection path off), `recordingCapability`/`startRecording`/`stopRecording` (the probe's answer; `supported:false` is reported through `onRecordingFailed` rather than silently doing nothing), and `requestSnapshot(preset)` over `SNAPSHOT_PRESETS` (`hd`/`fullHd`/`uhd4k`; `viewport` resolved on the main thread, the only place that knows the layout). `sandboxSupported()` gates Worker/OffscreenCanvas/WebGL2/transferControl. `detectTier()` is only the opening guess (GPU family regex, cores, `deviceMemory`, DPR, touch); measured behaviour overrides it everywhere else.
- **Worker.** `initRenderer` builds the renderer (antialias/shadows/powerPreference follow tier, ACES tone mapping) and wires `webglcontextlost/restored`. Context loss is handled, not faked: the swap banks every model texture via `context-restore.ts:collectModelTextures`, `webglcontextrestored` calls `reuploadTextures(RESOURCE_TEXTURES)`, and `renderFrame` stops calling `renderer.render()` while `CONTEXT_LOST` (presenting into a dead context was the silent half of the old bug). `loadProgram` runs the security sequence: instrumented `runtime` → `compileGuest` → facades + bounded `console` → `hardenRealm(globalThis)` (after compile, before run; `post`/`scheduleFrame`/`now` were captured into module scope beforehand) → `builder.toManifest()` → `priceModel` admission against `DEVICE_BUDGETS` → `realize` → atomic swap (old model disposed only after the new one realizes). Raw loads (no `runtime` twin) run `prepareProgram`'s gate + loop instrumentation themselves. **Boot is asynchronous, and the ordering is load-bearing.** `beginBoot` awaits `PhysicsWorld.warmUp()` before it calls `initRenderer`, because `initRenderer` ends in `hardenRealm(globalThis)` and hardening deletes `WebAssembly` (it is not in `HOST_RETAINED_GLOBALS`) — a Rapier runtime compiled after hardening can never start, which is why every physics model used to degrade to "the engine could not load on this device" while the code had no way to tell the device from the sandbox. The same warm-up also starts at module scope as a head start; that is a race, and the `await` is the guarantee. Because `ready` now arrives one compile later, every non-`init` message is parked in `deferredRequests` and replayed once boot completes — the host sends `init` and `load` back to back, and a `load` that overtook the boot used to hit `if (!state) return` and vanish (a viewer that loaded nothing, with nothing on screen to read). The frame loop `renderFrame`: `frame-compose.ts:renderGate` decides whether the frame can be empty (paused + nothing dirty ⇒ still, stats still publish with honest 0 fps); clamped delta (`maxDelta: 0.1`); physics steps publish probes and the stats carry the measured solver truth (`physicsStatus`: `physicsActive`, plus `physicsUnavailableReason` when a declared world failed to create — `03` R9 forbids reading "on" from the declaration); `pickPoint` raycasts a screen point to a world hit for notes, and `projectAnnotations` re-projects the pin set at most once per presented frame (touching no matrix at all when there are no pins); `resetCameraToInitial` restores the authored pose clamped to the model's own declared camera limits; a snapshot resizes, renders, captures and _verifies_ the restore so a 4K export cannot leave the canvas stuck at 4K; guest callback runs under `guard.reset(SANDBOX_LIMITS.frameDeadlineMs, 2_000_000)` — sustained overruns or a throw set `frameDisabled` with an explanatory notice instead of killing the model; declared motions `applyMotions` compose over `resetMotionDrivenInto`'s in-place base reset; `syncTransforms` writes by components; hover raycasts coalesce once per frame; `monitorLadder` uses 90-frame sustain with 1.35/0.85 bands and posts one `LADDER_NOTICES` sentence per step-down. **Liveness is the event loop's clock, not the presenter's**: the stats/metrics cadence is gated on `lastStatsMs` and fired by both the render loop and a wall-clock `setInterval` heartbeat (`TIMING.heartbeatIntervalMs`) — the presenter on a software-raster device delivers at 0.2–2 fps, so the between-stats gap otherwise ran to seconds against a ~4 s silence window and read as a hang (the second head of the demo-killer); a wedged loop cannot service timers either, so a true hang still crosses the window.
- **Extracted modules.** `camera-glide.ts` — cubic ease-in-out over `GLIDE_DURATION = 0.9` s interpolating the spherical `OrbitPose` (rig stays single source of truth); `fitDistance` fits both fov axes (portrait phones); `retargetGlide` re-aims at moving objects without restarting the clock; `isTapRelease` separates tap (≤`TAP_THRESHOLD_PX = 6`, one finger) from drag; `isUsablePose` blocks NaN cameras. `frame-rate.ts:computeFrameRate` — presented-frames-per-second between samples, 0 for a stalled loop, capped at `MAX_REPORTED_FPS = 240`. `physics-world.ts:PhysicsWorld` — Rapier in SI units (`GRAVITY = 9.81`), fixed `FIXED_DT = 1/60` accumulator capped at `MAX_SUBSTEPS = 3` (debt shed, never accumulated), `inferColliderShape` deduces colliders from the geometry builder name + bounding radius, mass from real `DENSITIES`, kinematic bridge into `simulatedParts`, NaN quarantine per body, idempotent `dispose()` guarding double `world.free()`. `quality-pin.ts:ladderDecision` — a pinned quality is measured but never acted on (warn once when unheld; step-up needs 2× the sustain). `frame-disable.ts` — the guest frame callback's circuit breaker: the disable (repeated overruns or a throw) scopes to the callback _alone_, while declared motion and the transform sync keep running, and it is recoverable — one probation frame per `FRAME_RETRY_PROBE_MS` window, cleared by any budget-holding run, re-armed by a failed probe. `context-restore.ts` — the WebGL recovery contract: `collectModelTextures` banks every texture reachable from the model's materials at swap time, `reuploadTextures` marks them for re-upload on `webglcontextrestored`; the worker also stops calling `renderer.render` while the context is lost instead of presenting into a dead context. `watchdog.ts:WATCHDOG` — `heartbeatTimeoutMs` (4 s base + 6× measured frame `frameMillis`, floor and 30 s cap; pre-first-frame = cap because the first frame compiles every shader) and `buildGraceMs` per tier (60/40/25 s), both consumed by the host's 1 Hz check; the tick judgement (`judgeWatchdogTick`) treats any message as liveness, records page-frame suppression (`renderSuppressed`: `document.hidden` _or_ a stalled main-thread rAF — the occluded-window case) without judging it, and re-arms a fresh silence window on the tick that sees the suppression lift, so returning to a background tab can never be mistaken for a hang.

## Flow

Sandboxed guest code → frames on screen: `SandboxHost.start()` → canvas transferred with the `init` request → worker builds renderer, posts `ready`, starts `loop` (rescheduled unconditionally; a frame exception posts a notice instead of killing the schedule) → host `load(code, seed, runtime?)` → fresh worker with build grace armed → worker `loadProgram` compiles, hardens, runs the guest, prices, realizes → `loaded {manifest, verdict}` + `notice` per admission adjustment → `renderFrame` presents via THREE to the OffscreenCanvas, which the browser composites onto the page's canvas element. Feedback flows back as `loaded`/`stats` (≥1 s cadence, gated on one publish per window from either the render loop or the wall-clock heartbeat, `RuntimeStats`)/`metrics`/`hover`/`selected`/`log`/`notice`/`snapshot` (`convertToBlob` PNG for the share flow)/`annotationPositions` (per presented frame, only while pins exist)/`capabilities` (the video probe's answer)/`pickedPoint`/`recording`/`recordingFailed`. Failure containment, layered: gate violations and guest throws → `loadFailed {message, timedOut, logs}` (`describeFailure` maps `GuestTimeoutError`/stack overruns to timeout class); a throwing frame callback disables animation, not the model; worker `error` events or watchdog silence → `kill(reason)` → `terminate()` → `onKilled` → fresh canvas, retry via `reload()`/`lastProgram`; context loss notices rather than a dead canvas.

## Integration

Worker side depends on `@edu3d/sandbox` (`compileGuest`, `hardenRealm`, `prepareProgram`, `createGuard`, `describeViolations`) and `@edu3d/engine` (`SceneBuilder`, `realize`, `priceModel`, `applyMotions`, `apiSurfaceSet`, `SceneError`/`GeometryError`/`MaterialError`), with `@edu3d/contracts` constants `SANDBOX_LIMITS`, `DEVICE_BUDGETS`, `QUALITY_LADDER`, `VIDEO_CLIP_LIMITS`, and the `AnnotationPin`/`ProjectedAnnotation`/`VideoRecordingCapability` wire types. Host side depends on `../dev-console.ts:devEnabled` and its formatters. Consumed by `routes/viewer/+page.svelte` (`SandboxHost`, `sandboxSupported`, `HostCallbacks`, `SNAPSHOT_PRESETS`, the `SerializableVerdict` type for the admissions panel, and every notes/export callback) and by `routes/loading/+page.svelte` + `components/generate-dialog.svelte` (`detectTier` to send `tier` in `GenerateOptions`). Tests pin the policy arithmetic: `watchdog.test.ts`, `quality-pin.test.ts`, `frame-rate.test.ts`, `camera-glide.test.ts`, `frame-compose.test.ts` (array-identity in-place reset), `physics-world.test.ts` (½gt² free fall, frame-rate independence, collider inference, double-dispose tolerance), plus `sandbox-host.test.ts`, `sandbox-worker-annotations.test.ts`, `sandbox-worker-export.test.ts`, `sandbox-worker-shots.test.ts`, `sandbox-worker-instruments.test.ts`, `sandbox-worker-swap.test.ts`, `context-restore.test.ts`, `frame-disable.test.ts`.
