# apps/web/src/lib/engine/

## Responsibility

The client-side engine host: the main-thread side of the sandbox boundary (`sandbox-host.ts`), the worker where all rendering happens on the learner's device (`sandbox-worker.ts`), and the DOM-free arithmetic extracted from the worker's hot path (camera glide, frame compose/rate, physics, quality, watchdog) so each rule can be tested without a GPU.

## Design

- **Protocol.** `sandbox-worker.ts:WorkerRequest`/`WorkerResponse` are the typed message dialects; `worker.postMessage` transfer-lists the `OffscreenCanvas`. `SerializableVerdict` strips the `Map`/`Set` fields of the engine's `AdmissionVerdict` so it survives structured clone.
- **Host.** `sandbox-host.ts:SandboxHost` owns the `<canvas>` because `transferControlToOffscreen()` is once-per-element — after any kill, `recreateCanvas()` replaces the spent element and `spawnWorker()` re-transfers. One worker per model: `load()` terminates the previous worker, so GPU objects, WASM heap and closures die with the realm (leak fix and correctness fix). Worker events are scoped to the worker they came from — a terminated worker's already-posted `MessageEvent` is ignored, so a stale `loaded`/`stats`/`error` can never touch the live host. `kill()` resets `buildingUntil`, pauses the empty replacement worker until a retry, and respawns on a fresh canvas. Every callback set is optional (`HostCallbacks`). `sandboxSupported()` gates Worker/OffscreenCanvas/WebGL2/transferControl. `detectTier()` is only the opening guess (GPU family regex, cores, `deviceMemory`, DPR, touch); measured behaviour overrides it everywhere else.
- **Worker.** `initRenderer` builds the renderer (antialias/shadows/powerPreference follow tier, ACES tone mapping) and wires `webglcontextlost/restored`. Caveat the code does not state: the restore loop iterates `RESOURCE_TEXTURES` (line 638) but nothing ever adds to that Set (grep: declaration + this read only), so no texture is actually re-uploaded — and `CONTEXT_LOST` gates only the guest callback, while `renderer.render()` (line 1306) keeps running against the dead context. `loadProgram` runs the security sequence: instrumented `runtime` → `compileGuest` → facades + bounded `console` → `hardenRealm(globalThis)` (after compile, before run; `post`/`scheduleFrame`/`now` were captured into module scope beforehand) → `builder.toManifest()` → `priceModel` admission against `DEVICE_BUDGETS` → `realize` → atomic swap (old model disposed only after the new one realizes). Raw loads (no `runtime` twin) run `prepareProgram`'s gate + loop instrumentation themselves. The frame loop `renderFrame`: `frame-compose.ts:renderGate` decides whether the frame can be empty (paused + nothing dirty ⇒ still, stats still publish with honest 0 fps); clamped delta (`maxDelta: 0.1`); physics step publishes probes; guest callback runs under `guard.reset(SANDBOX_LIMITS.frameDeadlineMs, 2_000_000)` — sustained overruns or a throw set `frameDisabled` with an explanatory notice instead of killing the model; declared motions `applyMotions` compose over `resetMotionDrivenInto`'s in-place base reset; `syncTransforms` writes by components; hover raycasts coalesce once per frame; `monitorLadder` uses 90-frame sustain with 1.35/0.85 bands and posts one `LADDER_NOTICES` sentence per step-down. **Liveness is the event loop's clock, not the presenter's**: the stats/metrics cadence is gated on `lastStatsMs` and fired by both the render loop and a wall-clock `setInterval` heartbeat (`TIMING.heartbeatIntervalMs`) — the presenter on a software-raster device delivers at 0.2–2 fps, so the between-stats gap otherwise ran to seconds against a ~4 s silence window and read as a hang (the second head of the demo-killer); a wedged loop cannot service timers either, so a true hang still crosses the window.
- **Extracted modules.** `camera-glide.ts` — cubic ease-in-out over `GLIDE_DURATION = 0.9` s interpolating the spherical `OrbitPose` (rig stays single source of truth); `fitDistance` fits both fov axes (portrait phones); `retargetGlide` re-aims at moving objects without restarting the clock; `isTapRelease` separates tap (≤`TAP_THRESHOLD_PX = 6`, one finger) from drag; `isUsablePose` blocks NaN cameras. `frame-rate.ts:computeFrameRate` — presented-frames-per-second between samples, 0 for a stalled loop, capped at `MAX_REPORTED_FPS = 240`. `physics-world.ts:PhysicsWorld` — Rapier in SI units (`GRAVITY = 9.81`), fixed `FIXED_DT = 1/60` accumulator capped at `MAX_SUBSTEPS = 3` (debt shed, never accumulated), `inferColliderShape` deduces colliders from the geometry builder name + bounding radius, mass from real `DENSITIES`, kinematic bridge into `simulatedParts`, NaN quarantine per body, idempotent `dispose()` guarding double `world.free()`. `quality-pin.ts:ladderDecision` — a pinned quality is measured but never acted on (warn once when unheld; step-up needs 2× the sustain). `frame-disable.ts` — the guest frame callback's circuit breaker: the disable (repeated overruns or a throw) scopes to the callback _alone_, while declared motion and the transform sync keep running, and it is recoverable — one probation frame per `FRAME_RETRY_PROBE_MS` window, cleared by any budget-holding run, re-armed by a failed probe. `context-restore.ts` — the WebGL recovery contract: `collectModelTextures` banks every texture reachable from the model's materials at swap time, `reuploadTextures` marks them for re-upload on `webglcontextrestored`; the worker also stops calling `renderer.render` while the context is lost instead of presenting into a dead context. `watchdog.ts:WATCHDOG` — `heartbeatTimeoutMs` (4 s base + 6× measured frame `frameMillis`, floor and 30 s cap; pre-first-frame = cap because the first frame compiles every shader) and `buildGraceMs` per tier (60/40/25 s), both consumed by the host's 1 Hz check; the tick judgement (`judgeWatchdogTick`) treats any message as liveness, records page-frame suppression (`renderSuppressed`: `document.hidden` _or_ a stalled main-thread rAF — the occluded-window case) without judging it, and re-arms a fresh silence window on the tick that sees the suppression lift, so returning to a background tab can never be mistaken for a hang.

## Flow

Sandboxed guest code → frames on screen: `SandboxHost.start()` → canvas transferred with the `init` request → worker builds renderer, posts `ready`, starts `loop` (rescheduled unconditionally; a frame exception posts a notice instead of killing the schedule) → host `load(code, seed, runtime?)` → fresh worker with build grace armed → worker `loadProgram` compiles, hardens, runs the guest, prices, realizes → `loaded {manifest, verdict}` + `notice` per admission adjustment → `renderFrame` presents via THREE to the OffscreenCanvas, which the browser composites onto the page's canvas element. Feedback flows back as `loaded`/`stats` (≥1 s cadence, gated on one publish per window from either the render loop or the wall-clock heartbeat, `RuntimeStats`)/`metrics`/`hover`/`selected`/`log`/`notice`/`snapshot` (`convertToBlob` PNG for the share flow). Failure containment, layered: gate violations and guest throws → `loadFailed {message, timedOut, logs}` (`describeFailure` maps `GuestTimeoutError`/stack overruns to timeout class); a throwing frame callback disables animation, not the model; worker `error` events or watchdog silence → `kill(reason)` → `terminate()` → `onKilled` → fresh canvas, retry via `reload()`/`lastProgram`; context loss notices rather than a dead canvas.

## Integration

Worker side depends on `@edu3d/sandbox` (`compileGuest`, `hardenRealm`, `prepareProgram`, `createGuard`, `describeViolations`) and `@edu3d/engine` (`SceneBuilder`, `realize`, `priceModel`, `applyMotions`, `apiSurfaceSet`, `SceneError`/`GeometryError`/`MaterialError`), with `@edu3d/contracts` constants `SANDBOX_LIMITS`, `DEVICE_BUDGETS`, `QUALITY_LADDER`. Host side depends on `../dev-console.ts:devEnabled` and its formatters. Consumed by `routes/viewer/+page.svelte` (`SandboxHost`, `sandboxSupported`, `HostCallbacks`, the `SerializableVerdict` type for the admissions panel) and by `routes/loading/+page.svelte` + `components/generate-dialog.svelte` (`detectTier` to send `tier` in `GenerateOptions`). Tests pin the policy arithmetic: `watchdog.test.ts`, `quality-pin.test.ts`, `frame-rate.test.ts`, `camera-glide.test.ts`, `frame-compose.test.ts` (array-identity in-place reset), `physics-world.test.ts` (½gt² free fall, frame-rate independence, collider inference, double-dispose tolerance).
