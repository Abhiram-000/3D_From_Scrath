# packages/sandbox/src/

## Responsibility

The sandbox's five defence layers plus the forgiving front door, one module per layer: `prepare.ts` (extraction, layer 0), `static-gate.ts` + `scope.ts` + `forbidden.ts` (layer 1), `instrument.ts` (layer 2), `compile.ts` (layer 3), `harden.ts` (layer 4), with `index.ts` as the package surface.

## Design

- `prepare.ts` — forgiving, opposite of the gate: `prepare.ts:extractProgram` returns the _largest_ fence (models emit illustrative snippets first), falls back to an unterminated-fence tail so truncation is detected rather than reported as "no code"; `prepare.ts:looksTruncated` is a string/comment-aware brace-depth scanner; `prepare.ts:prepareProgram` gates _before_ instrumenting and sets `ok:false` otherwise.
- `forbidden.ts` — frozen data only, no logic: `forbidden.ts:HOST_RETAINED_GLOBALS` (schedulers, `performance`, `createImageBitmap`, `ImageBitmap`) is subtracted from `FORBIDDEN_GLOBALS` to form `forbidden.ts:REALM_DELETIONS`, because the worker host runs the render loop in the same realm. Layer-triple redundancy is the design: gate rejects, compiler shadows, realm deletes (`forbidden.ts` header). `console` is in `GUEST_BINDINGS` so a model that cannot log is a model nobody can debug.
- `scope.ts` — `scope.ts:analyzeScopes(program)`: two `acorn-walk/ancestor` passes (declarations first, because hoisting makes single-pass resolution wrong); `var`→nearest function scope via `nearestFunctionScope`, `let/const/class`→`nearestBlockScope`; `patternNames` recurses nested destructuring; `isReference` is an explicit whitelist of non-reference positions (member property, property key, label, import specifier — the dangerous direction is permissive, hence no heuristic). Returns `ScopeAnalysis {scopes, freeReferences, maxDepth}`.
- `static-gate.ts` — `static-gate.ts:runStaticGate(source, options)`: never throws; early returns for empty/oversized programs (`SANDBOX_LIMITS.maxCodeBytes`); parses as `sourceType: 'script'` so `import`/`export` are syntax errors (rewritten as `module_syntax` when the message matches); `full` walk (not `simple`) for `RESERVED_PREFIX` identifiers because declaration names dispatch as `Pattern`; rejects `with` (undoes all scope analysis), forbidden members static _and_ computed-literal (`x['constructor']`, `globalThis['fetch']`); free references must be in `GateOptions.apiSurface` namespaces or `allowedIntrinsics`/`GUEST_BINDINGS`, else `unknown_api` — unresolved `x.method` is reported qualified so the repair pass deletes one line. Returns `GateResult{ok, violations≤64, byteLength, guardedLoops, apiCalls≤256}`. `describeViolations` dedupes by `kind:snippet` with counts + line numbers.
- `instrument.ts` — guard at loop-body top (before a `continue` can skip it), block wrapping for bare statements, replacement of `for (;;);` empty bodies, plus function-entry guards for declarations, expressions, and block-bodied arrows (unguarded `.sort(() => {…})` was the reviewer gap; recursion is bounded by wall clock, not stack depth). Edits are offset-sorted descending; loop-free programs come back byte-identical; `instrument.ts:isLoopNode` for classification.
- `compile.ts` — `compile.ts:compileGuest` prepends `'use strict'`, parameterizes guard + `GUEST_BINDINGS` + every shadowable forbidden name, `run(bindings)` passes `undefined` for anything not provided (that _is_ the shadowing) and `.call(undefined)`s the factory. `UNSHADOWABLE` (`eval`, `arguments`) are strict-mode SyntaxErrors as parameters — covered only by the gate and poison, which is why those layers exist.
- `harden.ts` — `harden.ts:hardenRealm(scope)` reports `{deleted, poisoned, frozen, resisted}`; non-configurable+writable properties are overwritten (`navigator`), refusals are _recorded_ not fatal (compiler shadowing still holds). `harden.ts:hardeningScript()` regenerates the same steps with the lists `JSON.stringify`-embedded for the `node:vm` realm; `harden.ts:auditRealm` reports leaks and probes `constructor.constructor`.

## Flow

Raw provider reply → `prepare.ts:prepareProgram` (`extractProgram` → `looksTruncated` → `static-gate.ts:runStaticGate` → `instrument.ts:instrumentLoops`) → `PreparedProgram`; `instrumented` is the only form ever handed to a realm. Host side then: `compile.ts:createGuard(now)` → `compile.ts:compileGuest(instrumented)` — built with `new Function` _before_ hardening, the ordering that lets the guest run where the facility that created it no longer exists — → `harden.ts:hardenRealm(scope)` or `hardeningScript()` inside a fresh `node:vm` context → `CompiledGuest.run(bindings)` with `{scene, geom, mat, M, console, random}`. Guest loops/frames re-`reset` the guard each phase; overrun exits as `GuestBudgetError`/`GuestTimeoutError`, other errors propagate as ordinary exceptions the host maps to diagnostics. `auditRealm(scope)` is the verification tail: a list of leaked names, empty when sealed.

## Integration

Dependencies: `forbidden.ts` ← `static-gate.ts`, `instrument.ts` (prefix reservation), `compile.ts`, `harden.ts` (via `REALM_DELETIONS`); `scope.ts` ← `static-gate.ts`; `static-gate.ts` and `instrument.ts` ← `prepare.ts`. Inward dep: `@edu3d/contracts` (`SANDBOX_LIMITS`, `GateResult`/`GateViolation`) and `acorn`/`acorn-walk` only — no engine, app, or server imports. Outward: `index.ts` re-exports everything hosts need and, per its header, deliberately exports _pieces_: `compileGuest`, `createGuard`, `hardenRealm`, `hardeningScript`, `auditRealm` are consumed by `engine/src/authoring/guest.ts` and both hosts (`apps/web/.../sandbox-worker.ts` uses `hardenRealm`; `engine/src/hosts/node-host.ts` uses `hardeningScript` inside `node:vm`); `prepareProgram`/`describeViolations` are consumed by `apps/server/src/services/pipeline.ts` and by engine tests as the gate fixture. `(function(){}).constructor` escapes, nested destructuring shadowing, and `for (;;);` are all exercises in the package's own tests.
