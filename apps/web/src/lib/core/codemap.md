# apps/web/src/lib/core/

## Responsibility

The app's model layer, deliberately UI-framework-free: the single owner of every network fetch (generation and tutor streams alike) and of the sessionStorage handoffs between pages, the honest loading-progress model, persisted settings, a real QR encoder for the share link, and small pure utilities for pointer coalescing, render pausing and the bounded chat context.

## Design

- `api.ts` — errors as values, never thrown. `generateStream(GenerateOptions)` returns `GenerateOutcome`, whose success branch carries the optional `galleryId` the terminal `ready` event named (the entry auto-save minted); stall policy is arithmetic imported from contracts (`STALL_TIMEOUT_MS = STALL_HEARTBEATS(4) × HEARTBEAT_INTERVAL_MS(10_000)`, `TOTAL_TIMEOUT_MS = CLIENT_TOTAL_BACKSTOP_MS`), measured from the last _event_ (heartbeats count) rather than a wall clock; a stream that ends without a `ready`/`error` terminal event is itself a failure. `AbortError` is disambiguated into `aborted` vs `run_overrun` vs `stalled` by whether the caller's own `signal` fired and which timer fired. `chatStream(ChatStreamOptions)` is the same NDJSON discipline in miniature for the tutor: forwards each `delta` through `onDelta` as it lands, ends on exactly one terminal `done`/`error`, and treats a stream that closes without one as a failure — the parsing lives here so no panel re-implements it. `BUNDLE_KEY = 'edu3d.bundle.v2'`: one JSON document (`StoredBundle {code, manifest, raw, galleryId?}`) under one key, consumed once (`takeBundle` discards corrupt entries), and `storedRuntime` extracts the server's instrumented `runtime` twin from `raw`. `galleryId` is the entry the server's auto-save minted for this generation; it travels with the bundle so the viewer can hand it to the publish path and UPDATE that entry rather than add a duplicate. `DEFAULT_COMPLEXITY = 'detailed'`.
- `qr.ts` — a real ISO/IEC 18004 encoder (byte mode, level M, versions 1–10), not a decorative pattern: `encodeQr` returns a module matrix or `null` when the payload does not fit, and `qrPixelSize`/`drawQr` render it into a caller-owned 2D context. A control that looks like it works and carries no data is worse than an absent one, so the share dialog reports "QR unavailable" rather than drawing pseudo-random cells. Correctness is pinned against an independent encoder in `qr.test.ts`.
- `loading-progress.ts` — `PHASES: PhaseSpec[]` gives each server `GenerationPhase` a contiguous 0–100 slice with a stage chip and local fallback `status`; `phaseOf` maps events; `ProgressModel.apply` is monotonic (a refinement re-running an earlier phase moves nothing back), `tick` eases `1 − e^(−t/τ)` toward but never past `to`; the on-screen sentence is the server's (`event.message`), the local one only a fallback. `view()` returns a plain object because a class instance is not reactive in Svelte — the page copies it into `$state`. `FactQueue` shuffles a topic-categorised pool (Fisher–Yates) with no repeats per cycle.
- `settings.ts` — zod-validated `UserSettings` from `@edu3d/contracts`; `loadSettings` returns contract defaults on missing/corrupt/throwing storage; `SettingsStore.update` applies patches through `safeParse` and refuses any patch that fails the schema, changing nothing; `StorageLike` is structural so tests pass a plain object.
- `pointer.ts` — pure: `toCanvasPoint` (relative to a rect cached at gesture start, so no per-move `getBoundingClientRect`) and `shouldSendPointerNow` (`down`/`up` immediate, `move` coalesced — the worker raycasts once per frame).
- `render-pause.ts` — `anyOverlayOpen` + `shouldPauseRender(overlayOpen, paused)`; deliberately non-latching: read on every call so a modal-closed model resumes unless the learner had paused it themselves.
- `model-context.ts:toContext` — mirrors the server's extraction client-side: ≤40 named parts (with `partsOmitted`), ≤24 parameters, objectives ≤8, description clipped to 1200, plus optional `selectedPartId`.

## Flow

A topic becomes a stream like this: `routes/+page.svelte` gates the topic with `validate-topic.ts:suspiciousContent`, then `api.ts:storeTopic`/`storeComplexity` and navigates to `/loading`. There `routes/loading/+page.svelte` reads back `takeTopic`/`takeComplexity` and calls `api.ts:generateStream` with `tier: detectTier().tier` (from `lib/engine/sandbox-host.ts`) and an `onEvent` callback; every NDJSON event goes to `loading-progress.ts:ProgressModel.apply`, the page ticks `tick()` per rAF and copies `view()` into Svelte `$state` (chips from `completedStages`, bar from `value`, wording from `status`). On the `ready` event `storeBundle({code, manifest, raw, galleryId?})` hands off and the route pushes to `/viewer`. The viewer `api.ts:takeBundle()`s it, records the bundle's `galleryId` so Publish updates that entry, loads `api.ts:storedRuntime(bundle)` into the sandbox host, and the conversational modes build requests with `model-context.ts:toContext(manifest, selectedPartId)`. A chat turn mirrors that path: `components/chat-panel-v1.svelte` calls `api.ts:chatStream`, painting each `delta` and finishing on the terminal `done`/`error`. Overlay/pause state flows through `render-pause.ts:shouldPauseRender` into `host.setPaused`; persisted choices flow through `settings.ts:SettingsStore` into the engine (quality pin, time scale) and into narration gating.

## Integration

Depends on `@edu3d/contracts` (`GenerationEvent`, `ChatEvent`, `ChatPersona`, `ModelBundle`, `ComplexityPreference`, `COMPLEXITY_IDS`, `GENERATION_PHASES`, `STALL_HEARTBEATS`, `HEARTBEAT_INTERVAL_MS`, `CLIENT_TOTAL_BACKSTOP_MS`, `SETTINGS_STORAGE_KEY`, `UserSettings`, `ModelContext`, `ModelManifest`) and on `lib/engine` only for `detectTier` (used by callers, not by this folder itself). Boundaries: `POST /api/generate` and `POST /api/chat` (both NDJSON, through `generateStream`/`chatStream`), plus non-streaming calls via `apiFetch` — `POST /api/gallery` + `GET /api/gallery/:id` (`components/share-modal.svelte`, `components/gallery-modal.svelte`), `POST /api/quiz` (`routes/viewer/+page.svelte`). Consumers: the three route pages, `components/generate-dialog.svelte` (`generateStream` + `ProgressModel`), `components/code-view-modal.svelte` (`peekBundleCode`), `components/chat-panel-v1.svelte` (`chatStream`), `components/share-modal.svelte` (`qr.ts`), `components/settings-modal.svelte` (`UserSettings`). Tests pin each contract: `loading-progress.test.ts` (monotonicity, unknown-phase milestone, `view()` plainness), `settings.test.ts` (corrupt/throwing storage, refused patch), `pointer.test.ts`, `render-pause.test.ts` (no latching), `qr.test.ts` (round-trips against an independent encoder), `api.test.ts` (stall/backstop attribution, one-terminal-event rule).
