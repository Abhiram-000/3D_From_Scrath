# apps/server/src/services/

## Responsibility

The server's entire service layer, one concern per file: the AI provider client, the headless audit kernel and its worker-thread host, the generation pipeline, the prompt architecture, the dual-backend gallery store, bounded model-context reduction, quiz validation, layered rate limiting, the bounded generation queue, the drain/lifecycle service, and static frontend serving with precompressed content negotiation.

## Design

- **`ai-client.ts` — `AiClient.complete(request: CompletionRequest): CompletionResult`** (class `AiClient(config: ServerConfig)`): dependency-free `fetch` to an OpenAI-compatible `/chat/completions`. Local failure vocabulary `AiFailureCode` (`quota|refused|truncated|timeout|network|malformed|status|cancelled`) with `classifyStatus` mapping HTTP status (429/503 → retryable `quota` with `retryAfterSeconds`; 404 on a model → retryable `status`; auth 401/403 → non-retryable; other 4xx → `malformed`). Retry discipline is typed: `MAX_ATTEMPTS = 3`, `BASE_BACKOFF_MS = 1_500` exponential or provider-dictated backoff; `REQUEST_TIMEOUT_MS = 540_000` guards generation-sized calls. **Model cascade** (`MODEL_CASCADES`) only ever adds models that exist on the _same_ provider (freeinference.org, generativelanguage.googleapis.com), advancing on `quota`/`status` failures; then a **cross-provider fallback** chain runs against `config.ai.fallback` (independent quota and model names). When `onProgress` is supplied the fetch is SSE-streamed and `consumeStream` reassembles it, throttling progress callbacks to every ~400 chars and counting `reasoning_content` as progress; **`completeStream(request, onDelta)` is the same streamed call wired to the chat route** — it forwards the provider's own content fragments through `onDelta`, so the server never re-chunks a blocking answer on a timer (that replay was the old chat behavior). completion classification distinguishes refusal finish vs `length`-finish truncation vs empty-reply malformity, and a stream dying mid-program with partial text is refused as `truncated`, never reported success — and (since the continuation protocol) that failure carries `partialText` + `usage` for the pipeline to continue from, and is NOT retried in-client (a whole-program re-roll has the same cut odds at full price). The learner's `AbortSignal` is pre-checked before spending the call and combined with the client's own timeout via `AbortSignal.any`; `cancelled` is never retried.
- **`audit.ts` — `auditModel(input: AuditInput): AuditOutcome`**: runs the AI's instrumented program in `node:vm` via `authorInNodeVm` from `@edu3d/engine/node-host` (direct subpath import to stay out of the browser barrel). This is the synchronous kernel; the pipeline reaches it through `audit-worker.ts:auditModelAsync`. The parameter-leverage dimension is the **differential sweep**: `sweepValuesFor` (fraction ladder 0/.25/.5/.75/1 + default for numbers; every value for bool/choice/color) at `SWEEP_TIMES [0, 1]`, counting a parameter live only if quantised state changes within a same-time slice, or if it is declaratively bound to a motion's `rate`/`amplitude` `{ param }`. Other dimensions score from measurable proxies: liveliness (`touchedParts()` fraction), information (parts with info text), completeness (hero + structure), representationFidelity (whole-model raw-primitive penalty plus per-part lookalike checks — spin + gear vocabulary or oscillate/pulse + spring vocabulary on a `RAW_PRIMITIVE_BUILDERS` builder, with `geometry.builder` provenance so an honest wheel is never flagged), pedagogy, colorSemantics, materialSemantics, cleanliness, attractiveness, detailEconomics and budget against `DEVICE_BUDGETS[input.tier]`; weighted by `AUDIT_WEIGHTS` into `report.score`, with `deficiencies` written imperatively (`finding` + `instruction`, `subjectId` for parameter leverage) so they can ride back as the refinement prompt, `blocked` for empty scenes. **Physics honesty** is the one place the audit reads intent against declaration: a model that declares physics intent (a `physics`-channel parameter, a `physics`-source read-out, or an `applyImpulse` interaction) but no `scene.physics` world is a `minor` worded as a trade-off — simulate, or say in `pedagogy.simplifications` that the motion is a depiction — so an honest animation is never accused; a declared world with no bodies is flagged the same way (a solver with nothing to move). Never throws; `builder.endParameterSweep()` returns the manifest unswept. `tests/audit.test.ts` regresses the reference turbofan against this.
- **`gallery-store.ts`**: interface `GalleryStore` (`list/get/put/delete/putSnapshot/getSnapshot/flush/close/init` + `announcement: StoreAnnouncement`). Factory `openGalleryStore(config)` implements the fallback ladder: no `DATABASE_URL` → `FileStore('unconfigured')`; `pg.Pool` (ssl only when the URL lacks `sslmode`, `max: 8`, idle-client `error` swallowed as a warning, `SELECT 1` reachability probe) → `PostgresStore` (idempotent schema: `blueprints` + separate `snapshots` bytes table; parameterised queries only; `INSERT … ON CONFLICT` upsert; `DELETE … RETURNING` truth; snapshots cached immutable under `/api/snapshots/<uuid>`); production-unreachable → `throw` (refuse to start); development-unreachable → `FileStore('unreachable')` with a distinct announcement (unconfigured vs unreachable send operators to different fixes). `FileStore` persists to `<dataDir>/gallery.json` debounced 2 s (`schedulePersist`), `flush()` writes temp+rename atomically, a corrupt file is quarantined (`gallery.json.corrupt-<ts>`) not deleted, `MAX_FILE_ROWS = 500` oldest-first eviction, snapshot files named `<uuid>.<ext>`. Shared: `sniffSnapshot(bytes)` magic-byte sniffing (PNG/JPEG/RIFF+WEBP form check/ftyp `avi*` brand) and `SNAPSHOT_MAX_BYTES = 4_000_000`.
- **`model-context.ts`**: `extractModelContext(manifest)` / `toContext(manifest)` produce the contracts `ModelContext` with the caps that keep chat/quiz cheap — 40 named parts (`partsOmitted` remainder), 24 parameters, 8 objectives, summaries ≤ 240 chars, description ≤ 1200.
- **`pipeline.ts`** (`runPipeline(topic, complexity, deps: PipelineDeps)`, `MAX_REPAIR_PASSES = 2`, `MAX_CONTINUATION_PASSES = 3`): never throws — every failure is a returned `PipelineFailure` (`upstream_failed|upstream_truncated|upstream_refused|upstream_quota|generation_unrepairable|generation_rejected|cancelled|rate_limited`) the route turns into a terminal event. Owns the heartbeat (`contracts.HEARTBEAT_INTERVAL_MS`) plus `enter(phase)` phase events; aborts early when `deps.signal.aborted`. **Continuation protocol**: when `replyLooksCut` fires (or the client handed back a `truncated` failure with `partialText`), the partial is sent as an ASSISTANT turn, `buildContinuationPrompt` asks for ONLY the missing remainder, and `stitchContinuation` reassembles one closed fence — restart detection (continuation restates the program), echoed-tail dedupe (single-line echoes must be ≥ 5 chars), mid-token/clean seam rules; a cut continuation keeps the loop going even when the seam is invisible to `replyLooksCut` (a cut landing on a comment line is a stealth cut), bounded at 3 passes, then `upstream_truncated` with a message naming the mechanism.
- **`prompts.ts`**: `PROMPT_VERSION = '2026-10-v8-physics-and-graphing'` (versioned; changes are gated on `battery-history.jsonl`). `buildGenerationPrompt` assembles the v8 architecture in deliberate order — three expert passes (domain scientist → instructional designer → 3D engineer), the verbatim `REFERENCE_MODEL_SOURCE` framed as a bar whose subject must never be imitated, `WORKED_MECHANISMS` (verified-executable 2–4 line patterns for instances/components/param-bound motion), the generated `describeApiSurface()` reference table, the builder cost ladder, build/frame budget discipline (20 s build, 50 ms frame, no geometry in `onFrame`), the NEVER list, the domain-grammar table, complexity/tier budget lines, `AUTHORING METHOD` scaffolding and the rubric self-check last. v8 adds a physics-solver form (a real Rapier/SI declaration with a body, mass/density and a joint to copy, because no rule existed so no generated model ever declared `scene.physics`) and three v1 rules that caught live failures: the **mathematics-and-graphing** rule (a function/equation/graph is drawn as a textbook graph with explicit axes, never a 3-D flourish — the highest-value rule, a sine wrapped into a helix was v1's most-repeated defect), **causal completeness** (build every link of source → mechanism → intermediate state → output; the floating-battery failure was a source with no edge to its mechanism), and the **domain-archetype classification** step that must name its choice (gear train, circuit, orbit, plotted curve, cell cross-section) before writing code. Others: `wrapTopic` (500-char fence labelling the topic untrusted data, anti-injection), `buildRepairPrompt` (model's own code + numbered errors + full API reference), `buildRefinementPrompt` (audit deficiencies + re-audit acceptance rule), `buildChatPrompt` (five personas: teacher/buddy/eli5/engineer/socratic), `buildQuizPrompt` (JSON-only array contract).
- **`quiz.ts`**: `validateQuizQuestions(raw): QuizValidation` pulls a JSON array out of prose/fence (`extractJson`), drops structurally invalid entries (non-string question, < 2 options, out-of-range `correctIndex`) with a `dropped` count, caps fields (question 400, options 6 × 200, explanation 800) and mints deterministic ids `q0…`.
- **`rate-limits.ts`**: `RateLimiter` fixed-window counters (`buckets: Map<key, Window>`, `check` returns exact `retryAfterSeconds`, `sweep` drops expired, `size` observable); `buildLimiters(config): LimiterSet` — api/write windows 1 min, generate/chat/quiz 5 min (AI runs are minutes). `clientKey(context, trustProxy, remoteAddress)` keys on the **socket address** (unforgeable; `isPrivateAddress` gate) and walks `x-forwarded-for` right-to-left skipping exactly `TRUST_PROXY` hops, only when the socket is private and the header carries more entries than trusted proxies; `main.ts` owns `remoteAddress = '127.0.0.1'` as fallback only. `limitWith` produces the 429 `rate_limited` envelope with `retry-after`. Battery exemption pair: `BATTERY_REQUEST_HEADER/VALUE` + `connectionAddress` (reads only `env.incoming.socket.remoteAddress`, fails soft) + `isLoopbackAddress` + `isBatteryExemption(header, address)` requiring header **and** loopback socket.
- **`static-pages.ts` / `static-encoding.ts`**: `STATIC_SITE_PRESENT` probes `index.html` under an absolute `STATIC_ROOT` (env `STATIC_ROOT` or `apps/web/build`) — the same fact handed to `resolveConfig`; `staticSiteMiddleware` is traversal-proof (resolved path must stay under the root), serves extensionless routes via the SPA shell (`/viewer?model=…` deep links), gives `/_app/` immutable caching, streams via `fileResponse` with a MIME table, and applies `encodedVariant` → `preferredEncoding(header)`: an RFC-faithful `Accept-Encoding` parser honouring `;q=` and refusals, `*` mapped to brotli, brotli winning ties as the smaller encoding, null meaning "serve the original bytes"; `Vary: Accept-Encoding` appended whenever a variant decision was made.

## Flow

Generation pipeline order inside `runPipeline` (each stage emits a `phase` event; a heartbeat timer covers silences; exactly one terminal event ends the stream):

1. **prompt** — `buildGenerationPrompt({ complexity, tier })` builds the system prompt.
2. **model** — `deps.ai.complete` with `onProgress` wired to immediate heartbeat sinks (`charsWritten`); failure → `mapAiFailure` → terminal `error`.
3. **extract** — `prepareProgram(first.text, { apiSurface: apiSurface().qualified, finishReason })` (from `@edu3d/sandbox`); if `prepared.truncated`, one continuation re-ask with the partial output as an assistant turn; still truncated → `upstream_truncated`.
4. **repair** — while `!prepared.ok && repairPasses < 2`: `buildRepairPrompt(prepared.code, [truncation, ...describeViolations(prepared.gate)])` → re-prepare; exhausted → `generation_unrepairable`.
5. **build** — `auditModelAsync({ code: prepared.instrumented, tier, seed: 0x5eed })` (the audit off the event loop, in its own worker thread); a build failure gets one repair round with the audit message (budget permitting) then re-audit; `report.blocked` → `generation_rejected`.
6. **refine** — only when `report.score < REFINEMENT_THRESHOLD` and major deficiencies exist: `buildRefinementPrompt` with `finding → instruction` lines, re-prepare + re-audit the revision, and keep it only if genuinely better (score ≥ and not blocked); a failed refinement keeps the first model.
7. **ready** — assemble `ModelBundle { manifest: finalAudit.manifest, code: prepared.code, runtime: prepared.instrumented, rawOutput, provenance { topic, promptVersion, repairPasses, refinementPasses, durationMillis } }` — shipping the _instrumented_ program as `runtime` is the rule (that is the string the audit validated) — plus a machine-readable audit summary `{ score, deficiencies, unboundParameterIds }`.

## Integration

- Depends on `@edu3d/contracts` (`GenerationEvent`, `GenerationPhase`, `ModelBundle`, `ModelContext`, `QuizQuestion`, `AuditReport`, `DEVICE_BUDGETS`, `AUDIT_WEIGHTS`, `HEARTBEAT_INTERVAL_MS`, `REFINEMENT_THRESHOLD`) and cross-package code: `@edu3d/sandbox` (`prepareProgram`, `describeViolations`), `@edu3d/engine` (`apiSurface`, `describeApiSurface`, `REFERENCE_MODEL_SOURCE`) and its `node-host` subpath (`authorInNodeVm`) for the vm audit.
- Consumed by `app.ts` routes (`runPipeline`, `AiClient` type, `buildChatPrompt`/`buildQuizPrompt`, `gallery-store.ts` types + `sniffSnapshot`/`SNAPSHOT_MAX_BYTES`, `limitWith`/`connectionAddress`/`isBatteryExemption`, `staticSiteMiddleware`, `validateQuizQuestions`) and by `main.ts` (`AiClient`, `openGalleryStore`, `buildLimiters`, `STATIC_SITE_PRESENT`, `lifecycle.beginDrain`/`waitUntilQuiet`), and by `pipeline.ts` (`auditModelAsync`, `lifecycle` generation counting). Boundary wire types: the NDJSON `GenerationEvent` stream and `ModelBundle` consumed by `apps/web/src/lib/core/api.ts` (`generateStream`), `ModelContext` shared with `apps/web`'s chat prompt builder; the pipeline routes never see raw provider errors — `mapAiFailure` translates the `AiFailureCode` vocabulary into `PipelineFailure` codes that map onto `ERROR_STATUS`.

- **`generation-queue.ts`** — `createGenerationQueue({ limit, maxWaitMs, drainSignal })`: the process-global FIFO generation admission queue. `run(task, { signal, onQueued, onGranted })` holds one slot per generation; waiters are `QueueWaitTimeoutError` (→ `rate_limited` via `describeQueueFailure`) / `QueueDrainedError` (→ terminal `draining`) / `QueueCancelledError` (→ `cancelled`) failures; `stats()` feeds `/api/health`'s `generationQueue` depth. The route's `runWithGenerationSlot` (app.ts) owns the waiting notice + heartbeats while queued; never blocks the event loop.
- **`audit-worker.ts` / `audit-kernel.ts`** — the audit leaves the event loop. `audit-kernel.ts` is the worker entry that runs the synchronous `auditModel` and posts back plain data (contracts' `AuditReport` + manifest are serialisable by design; no builder, closure or function ever crosses). `audit-worker.ts:auditModelAsync` spawns **a fresh worker per audit, always terminated** — a poisoned realm or a wedged build cannot leak into the next request — and races `AUDIT_WORKER_DEADLINE_MS` (`buildDeadlineMs × 2 + 5 s`) against the answer, terminating on cap and returning a `timedOut` failure rather than hanging the caller. Before this, `node:vm` ran inline and one generation's audit froze every other request (heartbeats, static responses, SIGTERM) for ~0.2 s typically and up to the build deadline; spawn cost is real (~410–450 ms module load) but per-audit and off-thread.
- **`lifecycle.ts`** — the process-wide drain service (`06`): `draining` + `drainSignal` (flipped by `main.ts`, read at every pipeline phase boundary and combined into every provider fetch so in-flight calls stop), and an `openGenerations` counter the pipeline increments for the lifetime of one `runPipeline` (increment first, decrement in `finally`). `waitUntilQuiet(timeoutMs)` resolves when the count reaches zero — this is what lets shutdown WAIT for open streams to be TOLD a terminal `error` before flushing and exiting — bounded so a wedged generation cannot hold shutdown forever. A module singleton rather than injected config, so the drain wires into the shared `AiClient` and `app.ts` with no route changes.
